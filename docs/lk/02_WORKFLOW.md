# Процесс работы над ЛК: роли и правила

## Роли

| Участник | Отвечает за | Не делает |
|---|---|---|
| **Владелец** (Мартынов Д. Н.) | решения, запуск запросов к боевой базе, приёмка, разрешение на мердж и деплой | — |
| **Claude** | ТЗ, база знаний, сбор фактов, промты для Cursor и ChatGPT, ревью итогов | не меняет код и базу напрямую |
| **Cursor** | код, тесты, ветки, PR, мердж после разрешения владельца | не подключается к боевому Медиалогу, не запускает запросы к нему |
| **ChatGPT** | аудит: архитектура, логика, безопасность, соответствие ТЗ и базе знаний | не пишет код в репозитории |

## Цикл одной задачи

1. **Claude** пишет промт для Cursor со ссылками на разделы ТЗ и базы знаний и
   критериями приёмки. Если для задачи нужен факт о базе, сначала — проверочный запрос
   из `03_VERIFICATION_SQL.sql`.
2. **Владелец** выполняет проверочный запрос (только `SELECT`; результат — схема,
   агрегаты или тестовый/свой профиль) и передаёт результат Claude. Выгрузка в файлы —
   `tools/Export-SqlResults.ps1` (см. ниже); в Claude передаётся zip из `tools/results/`.
3. **Cursor** делает ветку и PR, заполняет шаблон PR.
4. **ChatGPT** проводит аудит PR по промту `prompts/chatgpt-02-audit.md`.
5. **Claude** сводит замечания аудита в задание на исправление для Cursor.
6. **Владелец** проверяет на стенде (runbook), разрешает мердж.
7. Новые факты о базе Claude вносит в `00_KNOWLEDGE_BASE_MEDIALOG.md` с источником.

## Жёсткие правила

- База Медиалог — только чтение, кроме утверждённых ТЗ путей записи на приём. Каждый
  write на боевой базе выполняет только владелец: выключатель, белые списки пациентов и
  линий расписания, служебная учётная запись `svc_patient_api_rw`, журнал, integration-тест.
- Агенты (Cursor, ChatGPT, Claude) не получают пароли, `.env`, ПДн чужих пациентов.
  Для разбора — схема, агрегаты, тестовый профиль (`PATIENTS_ID=1`) и профиль владельца.
- Рассылка пациентам (`REMINDER_ENABLED`) включается только владельцем.
- Каждый PR — в GitHub, через ревью. Без зелёных тестов и без аудита (если он требуется
  по плану) мердж не делается.

## Выгрузка результатов SQL в файлы

`tools/Export-SqlResults.ps1` выполняет скрипт по пакетам (между `GO`) и сохраняет каждый
результирующий набор в отдельный CSV (`S03_1.csv`, `S03_2.csv` …), сводку `_summary.csv`,
журнал `_log.txt`, книгу Excel (лист на набор) и zip для передачи.

```powershell
cd <папка lk>
powershell -ExecutionPolicy Bypass -File tools\Export-SqlResults.ps1 -SqlFile 03_VERIFICATION_SQL.sql
#   -Only S3,S9        только выбранные блоки
#   -SqlLogin          SQL-вход (окно ввода пароля) вместо Windows-входа
#   -NoXlsx            без Excel
```

- Пакеты с `INSERT/UPDATE/DELETE/CREATE/ALTER/DROP/EXEC/GRANT/INTO…` скрипт не выполняет
  (пометка `SKIPPED`): создание логинов (05) и runbook 04 — только вручную в SSMS.
  Проверочная часть 05 выгружается тем же скриптом.
- Тайм-аут пакета 60 с; ошибка блока не останавливает остальные.
- Подключение подписано `Application Name = lk-verification-export`; пароль не сохраняется.
- CSV — UTF-8 с BOM и разделителем `;`, открываются в Excel двойным щелчком.
- Excel создаётся через модуль ImportExcel или установленный Excel; если нет ни того,
  ни другого — только CSV.
- Папку `results` не класть в общие каталоги: в ней строки тестового профиля и профиля владельца.

## Шаблон описания PR (`.github/pull_request_template.md`)

```markdown
## Что сделано
<!-- 2–5 строк; ссылка на пункт ТЗ, напр. «ТЗ §4 этап 1, п. 1.4» -->

## Медиалог
- [ ] Только SELECT (write не добавлен и не изменён)
- [ ] Если есть write: флаг по умолчанию выключен, integration-тест, решение владельца: <ссылка>
- [ ] Запросы ограничены пациентом/датой, без полных сканов больших таблиц
- [ ] Новые факты о базе: <ссылка на раздел базы знаний или «нет»>

## ПДн
- [ ] В логах только идентификаторы
- [ ] Пациент видит только свои данные (фильтр по patient_id из токена)

## Проверки
- [ ] go test ./... и go vet ./... зелёные
- [ ] Проверка на стенде по runbook: <что смотрели>
- [ ] Аудит ChatGPT: <не требуется | ссылка/итог>
```
