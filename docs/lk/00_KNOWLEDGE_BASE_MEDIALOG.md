# База знаний: МИС Медиалог сети МедКвадрат (для личного кабинета пациента)

Версия 1.5 — 15.10.2026 (результаты S0–S18 и прав `public` от 15.10.2026; сверка ChatGPT от 14.10.2026). Источники: этот проект (PR #1–#17, read-only проверки на стенде),
проект «Универсальный отчёт КЦ» (`Reports/КЦ_универсальный_отчет`, проверки 00K–12G),
расследование «интеграции страховых» (октябрь 2026), справка Медиалога (`Medialog_help_full.md`),
код репозиториев `medkvadrat-patient-api`, `medkvadrat-max-bot`, `medkvadrat-deploy` на `main`.

**Уровни достоверности:**
- **[П]** подтверждено запросом к базе или кодом/справкой;
- **[В]** высокая вероятность, есть косвенные доказательства, нужна одна проверка;
- **[?]** гипотеза или неизвестно.

Каждый новый факт добавляется сюда с источником. Факт, опровергнутый проверкой,
не удаляется, а помечается «ОПРОВЕРГНУТО» с датой — чтобы ошибка не вернулась.

## 8. Правила работы с базой, выведенные на практике

1. Только `SELECT`. Любой write — отдельное решение владельца и клиники.
2. Чтения ограничены окном и ключом (пациент, дата); без полных сканов больших таблиц в горячем пути.
3. В логи — только идентификаторы; ФИО, телефоны, email — только в теле ответа авторизованному клиенту.
4. Против боевой базы не запускать агентов разработки (Cursor и т.п.): их вывод уходит стороннему провайдеру.
5. Скриншоты и выгрузки для обсуждения — по тестовому/своему профилю или агрегатами.
6. Даты отдавать из SQL строкой (`CONVERT(varchar(16), …, 120)`), парсить в Go как Europe/Moscow. Зону каждого нового поля `datetime` проверять отдельно.
7. `NOLOCK`/`READ UNCOMMITTED` допускают чтение неподтверждённых, пропущенных и задвоенных строк. Для решений (свободно ли время, состоялась ли запись) — только обычное чтение; для витрин и статистики — по ситуации.
8. Права `public` в `Medialog` широкие (см. §1): «только чтение» обеспечивается только явными `DENY` у служебного логина, а не ролями. После каждого обновления Медиалога повторять проверку прав (блок 3 файла 05).
